Let’s start with handling form submissions. In source/controllers/projects.js, the edit handler checks validation, reads submitted fields from req.body, calls the model, then redirects:

const processEditProjectForm = async (req, res) => {
    const errors = validationResult(req);
    if (!errors.isEmpty()) {
        errors.array().forEach((error) => {
            req.flash('error', error.msg);
        });
        return res.redirect(`/edit-project/${req.params.id}`);
    }

    const projectId = req.params.id;
    const { organizationId, title, description, location, date } = req.body;
    await updateProject(projectId, title, description, location, date, organizationId);

    req.flash('success', 'Project updated successfully!');
    res.redirect(`/project/${projectId}`);
};

How would you explain the flow from submitted form data to the model update, and why do you think the handler checks for validation errors before calling updateProject?

For server-side validation, the projectValidation rules in source/controllers/projects.js check submitted fields on the server:

const projectValidation = [
    body('title')
        .trim()
        .notEmpty().withMessage('Title is required')
        .isLength({ min: 3, max: 200 })
        .withMessage('Title must be between 3 and 200 characters'),
    body('date')
        .notEmpty().withMessage('Date is required')
        .isISO8601().withMessage('Date must be a valid date format'),
    body('organizationId')
        .notEmpty().withMessage('Organization is required')
        .isInt().withMessage('Organization must be a valid integer')
];
