Let’s start with Express routing. In server.js, the categories route is:

app.get('/categories', async (req, res) => {
    const categories = [
        'Environmental',
        'Educational',
        'Community Service',
        'Health and Wellness'
    ];
    res.render('categories', {
        title: 'Service Project Categories',
        categories
    });
});

In your own words, what happens when a browser requests /categories, and why do you think this route sends the category list to res.render?

User: I am unsure please explain

Coach: That’s okay, HB. app.get('/categories', ...) tells Express: “When a browser requests the /categories page, run this function.” Express gives the function req (request details) and res (the response to send back).

The function creates a list of categories, then res.render('categories', { ... }) asks EJS to turn the categories template into HTML. It passes in the page title and category list so the template can display them—for example, <%= categories[0] %> displays “Environmental.”

What do you think the browser would show if the route rendered the template without passing in categories?

User: I dont know

Coach: That’s completely fine, HB. Without categories, EJS would try to evaluate <%= categories[0] %> but the variable wouldn’t exist in the template’s data, so rendering would fail and the page would likely return a server error.

Let’s look at a JavaScript language principle in the route function from server.js:

app.get('/categories', async (req, res) => {
    const categories = ['Environmental', 'Educational', 'Community Service', 'Health and Wellness'];
    res.render('categories', {
        title: 'Service Project Categories',
        categories
    });
});

Coach: Yes, it is intentionally simple: the array keeps the related category names together, and const says the variable won’t be reassigned.
